### The PNG and Wayback Machine problem

The Instagram audits develop this distinction further. Some large PNG files are served as `application/octet-stream`, causing browsers to download them rather than display them inline. That behavior had apparently motivated the substitution of smaller or more browser-friendly JPEG copies.

The conversation establishes a more precise interpretation:

* forced download does not mean the PNG is missing;

* non-inline display does not mean the file is corrupted;

* the Wayback Machine can still preserve the binary object;

* an archived file may have to be downloaded before it can be viewed;

* and the canonical PNG should remain in the repository inventory even if a JPEG preview is more convenient.

This produces a useful two-layer model:

1. **Canonical layer:** the exact repository file, preserved and linked by its real filename.

2. **Convenience layer:** an optional preview or derivative, clearly labeled as such.

The crucial recommendation is not to let the convenience object impersonate the canonical object.
